# VoyagerPhone · 远航浏览器版 0.8.16

[打开游戏](https://bradlytomsett.github.io/VoyagerPhone/)

VOYAGER V14.66 的单人星际沙盒。网页、Python 引擎和运行资源全部由 GitHub Pages 的 `docs/` 提供；引擎在浏览器 Web Worker 内通过 Pyodide 运行，无需游戏服务器、Codespaces 或 Docker。原始 `seed/` 保持不变。

## 开始游玩

1. 用新版 Chrome 打开游戏。首次加载约 20 MB，请等待“本机存档已就绪”。手机和电脑均可使用。
2. 打开“游戏设置”，填写自己的 API Key，并核对服务商当前可用的模型名称。预设地址为 `https://api.deepseek.com`，协议为 Chat Completions，预填模型为 `deepseek-flash`；也可填写兼容的 HTTPS 接口。
3. 保存设置，先用“问询”查看舰队、任务和账户。保存设置本身不会发起模型调用；“测试 API 连接”和发送指令会产生服务商费用。
4. 原存档没有开放场景和玩家视角。选择视角人物与开场地点，点击“建立新的游玩场景”，补充 AI 需要的信息。查看草案，点击“执行这一回合”后才正式保存。
5. 此后的“行动”先生成草案，再进行独立复核，由原引擎校验，最后等你确认。问询不推进游戏时间。

人物与地点可以按名称选择，指挥官位于人物列表首位。选择人物本身不会改变存档；指挥官首次建立场景时，必要的身份登记与视角绑定随草案一起等待确认。

## 原始资料与游戏记忆

“资料库”直接读取当前存档、任务、世界设定、规则与事件记录，按人物、店铺、地区和关键词检索；每条保留记录日期，原文位置在内部保留以供核对。余火、正式员工、雷托、熄炉-9、韩默、伊沃和马洛有可直接查看的摘要。查看资料无需 API Key，不推进时间，也不改写账户或资产。

22 份原始冷归档可勾选“包含历史归档”后按需解码搜索。旧状态、未确认草案与经营模拟保留原始性质，不当作已发生的交易。AI 每轮根据问题检索相关原文，同时遵守现有视角与知情限制；指挥官资料不会自动成为 NPC 的记忆。检索受上下文大小限制，没有命中不等于原始存档不存在该信息。

资料库提供 16 个主题入口，覆盖基地与总部、远星军、人物、熄炉与余火、产业采矿、科研探索、部署后勤、市场、组织地区、情报案件、库存、任务、剧情经营、型号设定和规则等。已逐项核对 52 个世界状态分区；内部路由、来源路径、机器编号和空字段不进入游戏界面，原档保留不变。

## 舰队档案与金额

点击任一舰队卡片，先按舰级合并展示同型舰数量；单舰卡片直接以舰名为标题，多舰卡片在舰级下列出全部舰名，未展开时也可辨认。展开后可查各舰名称、舰级数量、每舰固定设计/武器防护/战力封板与现行武备审计、设备数量与分布、型号性能目录，以及人员和完整原档。三舰队的现役数、持有数和具名单舰记录分开显示；旧计划与当前实装不混算。所有资料按需读取，不调用模型或改写存档。

远星军入口位于远航者舰队卡片内，快反部队入口位于暗影舰队卡片内，明确隶属关系。点击两部队的人员数量可查看每人基础战斗力 T：远星军及远航者人员按 8363-11-12 新封板 T=100，暗影快反按现行训练记录 T=70；不会套用旧舰员自卫 T=65 或旧外招 T=60。基地资料和重要数量分栏显示。远星军 4,234 人已包含在远航者 17,203 人内；暗影基地 110 人招募记录与后续 54 名固定指挥/保障人员按各自日期分别列出，不自动相加。舰内及编制里的武器、载具和装备名称可点击查看性能。

金币与铜币账户按 1 金币＝100 银币＝10,000 铜币拆分显示，不再用金币小数或巨额铜币数字代替。换算使用整数运算，保留到 1 铜币；灰币保持独立币种，概览显示约数，悬停可查原始精确余额。账户实际余额不变。

武器目录包含三类枪械、手雷/火箭筒/单兵导弹、舰炮、近防、发射单元和护盾，以及保障与爆破物。舰载武备按舰级固定设计或逐舰审计展开。普通枪弹、普通舰炮炮弹和普通舰载导弹按原规则作为系统自带配置，不伪造独立库存。

性能按现行航空 A／地面 G 口径解释，旧 C_final 字段作为整舰航空 A 的兼容名称保留。玩家完好区间型号按当前封板规则列出本型号上限名义值；原始区间仍可查看。多功能手雷六种模式沿用最新规则。

## 内部调动（无需 AI）

在“舰队 → 内部调动”中选择物资、人员或整舰转隶，选调出方、接收方与数量，核对前后数量后执行。支持舰船、三舰队公共库存、总部、基地、远星军、快反部队及自行建立的空仓库；有明确当前数量的物资才进入可调清单，历史采购和未交付计划不成为额外存货。军用/工业爆破物分开，以 kg 调拨；按件装备使用整数。

暗反1组作为快反部队的下属编组单列，可作为调入或调出位置；原有人员与配属装备从快反总账中分开，船员仍按所属舰船计数。旧浏览器存档首次读取时兼容分列，保留此前调动结果，不重新增加已调出的资源。

人员按人数与 T 分组转移，保持原 T，不自动修改具名人物的岗位或故事位置；整舰转隶携带已登记随舰人员和装备，保留舰名、性能和物理位置，不模拟航行。舰级模板保持原文，调动后的实装优先展示。首次登记采用明确的实物记录或原舰级固定编制，未单列型号的保持泛型；不把重复汇总当新库存。

工具使用独立的确定性调动账本，映射现有库存与编制字段，检查数量守恒并经原生暂存与原子保存提交；不会调用模型。浏览器扩展支持转隶后保留原舰名与序号空缺，身份依据仍绑定原始舰船登记。先持久保存确认意图，再提交与保存结果；关闭后使用原编号恢复。调动记录随存档导出和导入，原始 seed 文件不变。

## 进度、密钥与备份

- 进度自动保存在当前浏览器的 IndexedDB，包含网页回合航志和校验值；也可点击“保存游戏”立即保存，并查看最近保存时间。写入和引擎确认完成后才显示成功；失败可重试保存或导出备份。手动保存不推进游戏时间，也不确认未执行的草案。
- 指挥官问询采用舰队汇报口吻，正文不展示来源文件路径、内部编号与资料日期标签。现有回复显示时也会清理这类标注，真实行动日期、数量与未核实情况仍保留；内部证据与行动校验数据不变。
- 同一存档只允许一个标签页写入。出现“游戏已在另一个标签页打开”时，关闭另一个游戏页再刷新。
- 定期点击“导出当前存档”。换设备时使用“导入游戏存档”；导入会替换当前进度，请先导出备份。清除网站数据、移除浏览器配置或丢失设备可能丢失本机进度。
- API Key 默认只保留在本次标签页会话中；只有主动勾选才在本机长期记住。导出文件不含密钥。不要把密钥提交到仓库。
- AI 请求从浏览器直接发送到设置中的服务商，包含本轮玩家可见上下文与指令。接口必须允许来自 Pages 网站的跨域请求；不支持时需换用兼容接口。
- 生成中关闭页面不会自动重发模型请求。确认提交前先保存原回合意图，重开后沿用相同编号恢复，避免重复行动。
- 本版本没有游戏账号、多人联机和跨设备同步。每个浏览器拥有独立进度，关闭页面不会按现实时间自动推进游戏。

真实模型可用性需用自己的密钥在设置中测试。固定响应测试验证请求格式和异常处理，不代表真实 AI 的剧情质量或服务商账户权限。

## 构建与发布

`browser/` 是源码，`docs/` 是可直接发布的完整静态站点。固定 Pyodide 0.27.7 的运行时、SQLite/LZMA 包与许可证已放在 `docs/vendor/pyodide/`，运行时不依赖外部 CDN。

```bash
python scripts/build_browser.py
node tests/browser_model.mjs
node tests/browser_storage.mjs
node tests/browser_manual_save.mjs
node tests/browser_briefing.mjs
node tests/browser_ship_images.mjs
node tests/browser_money.mjs
node tests/browser_logistics_storage.mjs
python -m unittest tests.test_logistics -v
node tests/browser_logistics.mjs
python -m unittest tests.test_fleet_archive tests.test_world_archive -v
node tests/browser_fleet.mjs
python -m unittest tests.test_source_library -v
node tests/browser_sources.mjs
node tests/browser_commander.mjs
node tests/browser_wasm.mjs
```

WASM 测试在隔离副本中创建明确标为 SYNTHETIC 的场景，验证真实原生回合、确认、关闭后恢复、重复提交去重、快照、导出和导入；支持 Windows，不依赖本机 Linux `fcntl`。原有服务器测试可在 Linux 运行：`python -m unittest discover -s tests -v`。

发布设置：仓库 Settings → Pages → Deploy from a branch → `main` → `/docs`。必须提交完整 `docs/`，包括 `.nojekyll`、`engine-bundle.zip`、`python_stdlib.zip`、WASM 和两个扩展 wheel。`asset-manifest.json` 记录构建资源校验值。

## 代码布局

| 路径 | 内容 |
| --- | --- |
| `browser/` | 中文手机界面、Worker、模型直连、本机存储与 Python 适配器 |
| `docs/` | GitHub Pages 发布资源 |
| `backend/` | 复用的引擎桥接、回合与模型契约；Pages 无需运行服务器 |
| `seed/` | 原始引擎、Guard、规则与初始存档 |
| `tests/` | 固定模型报文、WASM 集成和原有服务端测试 |

20 张原始装备海报及用户提供的 M1、先锋-2至先锋-5动力甲、自有步枪、自有手枪、外购军用步枪、外购军用手枪、民用步枪及民用手枪原图已按型号接入装备卡片、性能详情及资料库图册，涵盖机器人、无人机、装甲车辆和民用车辆。霍克组与余火配送的路狐-4分别对应各自图片。缩略图按需加载，点击查看无损原始 PNG；图片和网页资源独立存放，不写入游戏存档，不用海报文字覆盖现行库存或性能。图片导入脚本使用原始索引核对两个来源 ZIP 及包内 20 张 PNG 的 SHA-256。

复杂战斗、多存档和语音尚未接入网页。未接入的机制不会由 AI 伪造为已执行。

远航者舰队12种舰级均配有内置 image_gen 生成的舰型插图，尺寸与主用途按原始舰级介绍核对。舰级卡片默认按110至920米的舰长比例显示，可切换“放大细节”，单舰详情与舰级资料也可查看原图。探索者突出科研探测设备、巨钳突出机械臂、母巢突出坞舱、西湖突出补给结构。插图是外观示意，不改写实装、武备数量、性能或存档；原PNG与网页缩略图独立存放，生成提示词保存在 browser/assets/ships/prompts.md。
