## 改动与所有权

32_knowledge_policy：知识索引 V3 一次建立事实、学习、旧披露位置、旧 viewer 的获知集合、别名反向映射、纠正与主体索引。按 scene/viewer 缓存递归冻结的结果，公开返回时复制。跨别名按原披露物理位置归并；保留旧隐式 observer 获知和显式来源映射的区别，不擅自修复或伪补旧知识。未知纠正仍不会泄露给角色。可变事务状态不使用该索引。

28_snapshot_service：公共 read 继续深拷贝，仅增加可审计复制计数；内部 read_view 保持递归冻结和同快照复用。06、19、21、22、27、29、32、35、41、42、43 中仅经审查的纯读函数改用视图，输出分支作必要复制。19b_transaction_service 把 consistency_repairs 纳入现有去重范围。未堆叠新的全局读包装。SOURCE_MANIFEST 的版本、摘要、imports／exports 经刷新并构建等价。

## 正确性与恢复

51 项不同的回归和定向用例全部通过；详见 audit/v1459/validation_summary.json。包括第一批历史所有权／验证复用／静态检查、普通查询等价和返回对象隔离、多角色及未知纠正、原 ID 原负载重试、机械与对白原子提交、真实授权停点、缓存损坏／不可写／并发、进程中断的 journal／组件／manifest／回执／清理阶段、未知改写拒绝，以及一致性修复在 events 与 manifest 后中断恢复。

新增实际可运行的合成宿主演示已执行成功：engine_loads=1、prepare_requests=1、submit_requests=1。演示在新副本中使用精确 payload 比对，仅为 SYNTHETIC 授权，绝不成为正式用户的默认授权器。

初期开发材料重封装使迁移目录中已完成事务证明与新 manifest 不一致，Guard 按设计拒绝。受影响案例从不带 .runtime 的全新来源目录重跑通过，未削弱或绕过恢复检查。另修订了新测试夹具保留的 Engine 2.69.0 版本断言；跨版本业务等价检查排除维护后本应变化的身份／诊断元数据。原始尝试与通过的重跑记录均保留，汇总逐项指向 verified_in。正确性并行运行的 seconds 不能作为性能数据。

## 守恒、交接和限制

state、tasks、rules、catalog 四份 JSON、全部原冷归档及 Guard 与实际 V14.58 输入逐字节相同；旧逻辑事件和物理事件正文不改，仅追加一条零时间、changes=[] 的维护事件。游戏时间 8363-12-10T17:20:00，远航日 691。原 READY_WITH_LIMITATIONS、经营证据缺失与历史未模拟缺口保留。

完整 ZIP 按 manifest 收集全部实际文件及开发材料，不包含 .runtime、对象池、派生缓存、测试副本或任何外部目录引用依赖。快照仍含完整实际路径文件，无格式迁移要求；外置守卫与包内 guard.py 同字节。新包在空目录仅携 ZIP 与外置守卫校验和启动。使用方法见 CONTINUE_V14_59.md；明确迁移脚本见 performance_batch2_followup_migrate.py，原则上使用已经完整升级的新 ZIP 即可。

性能样本与回归使用封装前冻结源码，原始 manifest 摘要已记录；其后只加入审计材料、说明和测试夹具修订，执行模块与业务数据不再变化。最终重新冻结开发清单，并再次做构建等价、完整检查、ZIP／外置守卫绑定和空目录冷启动。
